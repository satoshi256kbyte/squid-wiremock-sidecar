# テスト用 API の httpbin.org

AWS 上の E2E テストで叩く外部 API として、`httpbin.org` を使う。
ローカルと CI は WireMock を使うので、`httpbin.org` には接続しない。

## httpbin.org とは

HTTP のリクエストとレスポンスを確かめるための、公開されたテスト用サービス。
オープンソースで、誰でも認証なしで使える。
指定したステータスコードや遅延で応答を返せるため、クライアントのリトライやタイムアウトの確認に向く。

## 使い分け

| 環境 | 叩く先 | プロトコル |
| --- | --- | --- |
| ローカル | WireMock（`api.example.com` の名前で転送） | HTTP |
| CI（GitHub Actions） | WireMock（同上） | HTTP |
| AWS の E2E テスト | `httpbin.org` | HTTPS |

Squid は HTTPS を復号せず、`CONNECT` でトンネルを通す。
このため Squid のログには、API が返した 500 や 429 は残らない。
ステータスの確認は、Client のログ（`CLIENT_STATUS`、`CLIENT_DIAG`）で行う。

## 主なエンドポイント

| パス | 動作 | 使いどころ |
| --- | --- | --- |
| `/status/200` | 200 を返す | 正常系 |
| `/status/500` | 500 を返す | 5xx のリトライを使い切る確認 |
| `/status/429` | 429 を返す | 429 のリトライを使い切る確認 |
| `/delay/5` | 5 秒待ってから 200 を返す | タイムアウトの確認 |
| `/get` | 受け取ったリクエストの内容を JSON で返す | プロキシ経由の疎通 |

## 注意

- 公開サービスなので、可用性の保証はない。混んでいるときは 502 や 503 を返すことがある。
- 負荷をかけない。E2E テストは、少ない回数の要求にとどめる。
- 認証情報や、実データを含む要求を送らない。
- `/status/500` は毎回 500 を返す。「500 の後に 200」は再現できない。
  このシナリオ（`error-500-then-200`）の確認は、WireMock を使うローカルと CI で行う。
- `/delay/{秒}` の上限は 10 秒。
