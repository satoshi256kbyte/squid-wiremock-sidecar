# M03 clarify

## 確定事項

| 論点 | 決定 |
| --- | --- |
| マッピング方式 | WireMockの静的JSONマッピングをGit管理し、Compose起動時に自動ロードする |
| レスポンス本文 | マッピングから分離し、`__files/`のJSON本文として管理する |
| エラーシナリオ | 500、503、429をそれぞれ独立したパスで定義する |
| レート制限 | 429レスポンスに`Retry-After: 2`を付ける |
| 遅延シナリオ | 100msと5000msの2種類を定義し、後続のタイムアウト検証で利用する |
| 検証対象 | WireMockの8080番ポートへ直接アクセスし、Squid経路はM05で検証する |
| 状態遷移 | 管理APIによる動的マッピング追加やシナリオ切り替えはM06以降の対象とする |
| 不正定義検証 | ホストの`python3`で全JSONの構文とマッピング必須項目を検証する |

## 対象外

- Test Clientの実装
- SquidのallowlistとWireMockへの転送設定
- リトライ、バックオフ、タイムアウト制御
- WireMock管理APIを使った実行中の状態遷移
