# M03 WireMockシナリオの仕様

## 1. 目的

WireMockの応答シナリオをJSONファイルとして管理し、後続Issueが再利用できる
正常系・異常系の契約を固定する。

## 2. 対象範囲

- `wiremock-scenarios/mappings/`の静的マッピング
- `wiremock-scenarios/__files/`のレスポンス本文
- HTTP 200の正常応答
- HTTP 500、503、429の異常応答
- `Retry-After`ヘッダー
- 100msおよび5000msのレスポンス遅延
- Composeによるシナリオの自動マウントとWireMock起動時ロード
- JSON構文とマッピング構造の静的検証

## 3. 機能要件

| ID | 要件 |
| --- | --- |
| FR-301 | 正常系のGETリクエストがHTTP 200とJSON本文を返す |
| FR-302 | HTTP 500とJSON本文を返すシナリオを定義する |
| FR-303 | HTTP 503とJSON本文を返すシナリオを定義する |
| FR-304 | HTTP 429と`Retry-After`ヘッダーを返すシナリオを定義する |
| FR-305 | 100msと5000msのレスポンス遅延を再現する |
| FR-306 | マッピングと本文を別JSONファイルとしてレビュー可能にする |
| FR-307 | Compose起動時に静的マッピングを自動ロードする |
| FR-308 | 不正なJSONまたは必須項目不足のマッピングを検出する |

## 4. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-301 | シナリオ変更時にアプリケーションコードを変更しない |
| NFR-302 | M01のサービス名、ポート、ネットワーク契約を壊さない |
| NFR-303 | M03ではWireMock管理APIによる実行中の状態遷移を扱わない |
| NFR-304 | シナリオ本文とマッピングをGit差分で確認できる |

## 5. シナリオ契約

| シナリオ | パス | ステータス | 追加条件 |
| --- | --- | ---: | --- |
| 正常系 | `/api/users/123` | 200 | JSON本文 |
| 内部エラー | `/api/error-500` | 500 | JSON本文 |
| 利用不可 | `/api/error-503` | 503 | JSON本文 |
| レート制限 | `/api/ratelimit` | 429 | `Retry-After: 2` |
| 短い遅延 | `/api/slow-100` | 200 | 100ms遅延 |
| 長い遅延 | `/api/slow-5000` | 200 | 5000ms遅延 |

## 6. 完了条件

- [ ] 各シナリオがJSONファイルとしてレビュー可能である
- [ ] WireMock起動時にマッピングが自動ロードされる
- [ ] 各シナリオのステータス、ヘッダー、本文、遅延を検証できる
- [ ] シナリオ変更にアプリケーションコードの変更が不要である
- [ ] 不正なJSONと必須項目不足を検出できる
- [ ] M03のSpec Kit成果物と検証手順が保存されている
