# MVP の仕様（スリム版）

元の要件は [docs/requirements.md](../../docs/requirements.md)。この仕様は、それを満たしているかを実機で確かめた記録である。
Spec は、この1ファイルだけにする。分割しない。

## 目的

ECS のサイドカー構成（Client、Squid、WireMock）をローカルと CI で再現し、
HTTP クライアントのリトライとタイムアウトを、実通信の E2E で確かめる。

## 範囲外

単体テスト、スクリプトの中身を読む検査、MiniStack の contract、品質ゲートのスクリプト、
仕様と計画を何本にも分ける運用。テストは E2E だけにする。ビジネスロジックのテストは、必要になったときに足す。

## 指摘

1. **R3 を満たしていない。**
   `swsc-pause` の namespace で `curl https://example.org` を、プロキシ指定なしで実行すると 200 が返る（実測）。
   プロキシ経由でも許可外は 403 になるが、Client が `HTTP_PROXY` を使わなければ、外部へ直接出られる。
   原因: ネットワークが通常の bridge で、`--internal` ではない。WireMock をホストの 8080 へ公開するために、
   `--internal` にできない。
   影響: 「完全に閉じた」状態を、E2E は保証していない。外部 API を呼ぶコードが、プロキシを迂回しても検査が通る。

## 決めたいこと（Clarify）

Q1. 指摘 1 をどうするか。

| 案 | 内容 | 費用 |
| --- | --- | --- |
| A | 直すのをやめ、この仕様に「閉域はプロキシの許可リストで担保する。直接接続の遮断は保証しない」と明記する | 文書のみ |
| B | E2E に「プロキシを使わない直接接続が失敗する」検査を足し、ネットワークを `--internal` にする。WireMock の管理 API は、ホストからの公開をやめ、コンテナ経由で呼ぶ | 実装の変更が中程度 |
| C | Client のコンテナだけ、外部への経路を断つ（`iptables` など） | 権限と環境依存が増える |

推奨は A。MVP の目的はリトライの検証で、直接接続の遮断は目的の外。要件が必須とするなら B。

## 計画と作業（Plan と Tasks）

- Q1 が A の場合: この仕様の R3 を「プロキシの許可リストで担保」に直し、`docs/requirements.md` の 4 章の文言も合わせる。
- Q1 が B の場合: 次を行う。
  1. `scripts/e2e-runner.sh` のネットワークを `--internal` にし、WireMock の公開を外す。
  2. `scripts/e2e-lib.sh` の WireMock 管理 API の呼び出しを、コンテナ内からに変える。
  3. `scripts/e2e-scenarios.sh` に、直接接続が失敗する検査を足す。
  4. `npm run test:ci` と4シナリオの `test:ci` が通ることを確かめる。
