# M08実装タスク

## 1. 進め方

`plan.md` 11章の11実装単位（U1からU11）を、T801からT811に1対1で対応させる。
品質ゲートの実行をT812として追加する。
各タスクは、対応する検査が通ってから次へ進む。検査は先に失敗するケースを書いてから実装する。
リポジトリのファイルを書き換える検査は書かない（`plan.md` 13章）。

### 1.1 検査コマンドの共通事項

| 層 | コマンド | Docker |
| --- | --- | --- |
| unit | `sh tests/m08-e2e-suite.sh unit` | 使わない。`docker-compose`をPATHから外しても通る |
| smoke | `sh tests/m08-e2e-suite.sh smoke`（引数なしも同じ） | Composeを使う |
| 名前指定 | `sh tests/m08-e2e-suite.sh smoke error-500-then-200` | Composeを使う |

このMacでColimaを使う場合は、Composeを使う検査の前に`colima status`を確認し、
`DOCKER_HOST=unix:///Users/satoshi/.colima/default/docker.sock`を設定する。
Composeは`docker compose`ではなく`docker-compose`を使う。

### 1.2 全タスク共通の受け入れ条件

次の条件は、各タスクの受け入れ条件に加えて、すべてのタスクに適用する。

後始末

- T801以外でComposeを使ったタスクの終了時に、`docker-compose ps -a -q`が空である
- T801の実験は、プロジェクト名`m08-q810`を`docker-compose -p m08-q810 down --remove-orphans`で回収する。
  T801の残存確認は`docker-compose -p m08-q810 ps -a -q`が空であること（`down`の後、コピーを消す前）とする
- 検査が作る一時ディレクトリ（`mktemp -d`）は`trap`で消え、終了後に残らない
- 作業で作った`$KIROCREW_SCRATCH`配下のコピーとログは、タスクの終了までに削除する。`/tmp`は使わない
- 失敗経路でも、終了コードが元の値を保つ

コミット対象からの除外

- `git add`はファイルを名指しで行い、`git add .`、`git add -A`、`git add -u`は使わない
- `$KIROCREW_SCRATCH`にあるコピー、実験の生ログ、一時ファイルをリポジトリへ持ち込まない
- コミット対象に`$KIROCREW_SCRATCH`の写しが残っていないことを、`git status --short`で確かめる
- このspecのタスクでは`git commit`、`git push`、PR作成を行わない（コミットは利用者の指示を待つ）
- 公開物（文書、レポート、ログ）にAWSアカウントID、認証情報、実ARNを書かない（NFR-807）

### T803: シナリオ表と実測

| 項目 | 内容 |
| --- | --- |
| 要件 | FR-802、FR-803、FR-804、FR-805、FR-806、NFR-802 |
| 触るファイル | `tests/m08-e2e-suite.sh` |
| 依存 | T802、T801の分岐結果 |
| 並列 | 不可（検査ファイルを共有） |
| 受け入れ条件 | `unit`の期待値表、抽出、固有の検査が通る。読み取れない項目が`-`になり、不一致の扱いになる |
| 検査コマンド | `sh tests/m08-e2e-suite.sh unit` |

- `scenario_spec`を`case`で実装する。配列は使わない（POSIX sh）。表の値は`plan.md` 3.2のとおり
- `slow-5000`の`wiremock`は、T801の分岐で確定する。「記録されない」と「揺れる」の場合は`-`にする
- 期待値の`wiremock`が`-`のとき、`parse_client`は`wiremock_count`を呼ばず`-`を出す
- パスは`scenario_spec`に二重に書かず、`scenario_path`の結果を使う。4名が`scenario_path`で引けることを`unit`で確かめる
- `parse_client`は、標準出力の`CLIENT_STATUS=`と、標準エラーの`CLIENT_DIAG result=`と`retry attempt=`の行から、実測値の文字列を組み立てる
- `extra_checks`は、`plan.md` 3.5の4種（全シナリオの`retry`行数、500後の1回目の行、429の3本と`capped=0`、タイムアウトの標準出力が空）を検査する
- 正しい例では通り、1語だけ崩した例（`wait=2`、`capped=1`、標準出力が空でない）では落ちることを`unit`で確かめる
- 期待値が`wiremock=-`のシナリオで、`wiremock_count`が0を返しても`PASS`になるケースを`unit`に足す
- `wiremock_count`はM06、M07と同じ定義を複製し、共通化しない。`scenario-lib.sh`は変更しない
- 429の総試行4とリトライ3は固定値で持ち、`retry-lib.sh`の`RETRY_MAX_ATTEMPTS_429`の既定値（3）との整合を`unit`で確かめる
- `RETRY_MAX_ATTEMPTS_429`の既定値の読み取りは、`apply_config_defaults`をサブシェルで呼ぶ

### T805: 実行ループ

| 項目 | 内容 |
| --- | --- |
| 要件 | FR-801、FR-807、FR-808、FR-811、NFR-806 |
| 触るファイル | `tests/m08-e2e-suite.sh` |
| 依存 | T804、T801の分岐結果 |
| 並列 | 不可（検査ファイルを共有） |
| 受け入れ条件 | `unit`の続行と停止、順序の独立のケースが通る。直列に実行される |
| 検査コマンド | `sh tests/m08-e2e-suite.sh unit` |

- `run_suite`、`run_one`、`suite_reset`、`run_client`を実装する。外部へ触る3点は関数経由にする
- 各シナリオの前に`wiremock_reset`と`wiremock_verify_reset`を呼ぶ
- `run_client`は`-e TEST_API_PATH=<scenario_pathの結果>`と上書き設定の`-e 名前=値`を渡す。`unit`のスタブで`-e TEST_API_PATH=`の引数が渡ることを確かめる
- リセット確認が失敗したら、そのシナリオを`FAIL`（未実行）、残りを`NOT_RUN`にして、ループを抜け、終了コード1にする
- アサーションが失敗しても次へ進み、最後に全体の合否を出す
- 終了コードは、全件`PASS`なら0、それ以外は1とする
- `unit`で、`suite_reset`、`run_client`、`wiremock_count`の3関数をサブシェルで差し替える。
  本番の関数に差し替え用の分岐は入れない
- 3番目だけ不一致にしても4番目まで実行されること、3番目のリセット確認の失敗で4番目の`run_client`が呼ばれないことを確かめる
- 実行順を逆にしても、各シナリオの合否が変わらないことを確かめる（FR-808）
- シナリオの開始と終了を`date +%s`で取り、`scenario <名前> elapsed=<秒>`を標準エラーへ出す。`$SECONDS`は使わない
- T801が「遅れる」の場合のみ、`slow-5000`の後に`wiremock_count`を1秒おきに読む待機を入れる（上限10秒、超えたら`FAIL`）

### T806: `smoke`の起動と後始末

| 項目 | 内容 |
| --- | --- |
| 要件 | FR-813、NFR-801、NFR-804 |
| 触るファイル | `tests/m08-e2e-suite.sh` |
| 依存 | T805 |
| 並列 | 不可（検査ファイルとポートを共有）。ただしT809の文書本体とは並列にできる |
| 受け入れ条件 | `smoke`が起動して畳める。終了後に`docker-compose ps -a -q`が空である |
| 検査コマンド | `sh tests/m08-e2e-suite.sh smoke`。続けて`docker-compose ps -a -q` |

- M07の`smoke_run`と同じ方式にする。`down --remove-orphans`、`up -d --build squid wiremock`、準備完了の待機を行う
- `unit`が落ちたら、Composeを起動しない
- `trap`は、`EXIT`で`cleanup`、`INT`で`exit 130`、`TERM`で`exit 143`にする
- `cleanup`の順は、`rc=$?`の保存、コンテナのログ出力（`rc`が0以外のとき）、`cleanup: reset attempted`、
  `wiremock_reset`、`down --remove-orphans`、一時ディレクトリの削除、`exit "$rc"`
- 各処理が失敗しても、次の処理を続ける（`|| true`）。リセットの失敗は無視し、`cleanup: reset failed (ignored)`を残す
- 開始前にも`down --remove-orphans`を呼び、前回の残りを混ぜない
- コンテナのログは`docker-compose logs --no-color --tail 100 squid wiremock`で、1回の実行で1度だけ出す
- ポート3128と8080が空いていない場合は、起動せず報告する

### T808: 失敗の注入

| 受け入れ条件 | 失敗経路の終了コードが1、130、143で、どの経路でもコンテナと一時ディレクトリが残らない |
| 検査コマンド | `sh tests/m08-e2e-suite.sh smoke`（`plan.md` 4.2の順5から7） |

- アサーション失敗は、サブシェルで`normal`の総試行を2と期待させ、本物の`run_suite`を実通信で実行する
- 終了コード1、`normal`が`FAIL`、`error-500-then-200`が`PASS`、標準エラーにシナリオ名と再現コマンドと診断ログがあることを確かめる
- リセット確認の失敗は、サブシェルで`wiremock_verify_reset`を1回目は成功、2回目は失敗に差し替える
- 1番目が`PASS`、2番目が`FAIL`（未実行）、3番目以降が`NOT_RUN`、終了コード1、2番目以降でクライアントが呼ばれないことを確かめる
- Compose起動失敗は、本物の検査入口を子として起動し、`COMPOSE_FILE`に存在しないファイルを渡す
- 子が1で終わり、`cleanup: reset attempted`がある。子の一時ディレクトリが空で、`docker-compose ps -a -q`が空であることを確かめる
- `INT`と`TERM`は、Pythonで子を起動し、管理APIが応答してから送る。終了コードは130と143
- 子の信号の既定の動作は`preexec_fn`で戻す。子の待機は`sleep`の短い間隔のポーリングにする
- 子には`M08_NESTED=1`を渡す。この変数は再帰を止める以外の挙動を変えない
- 検査全体に上限時間を設ける。超えたら子を`kill`して失敗にする
- 親の`trap`でも、子のコンテナと一時ディレクトリを回収する
- `INT`と`TERM`の観測値が130と143と異なる場合は、観測値で`spec.md`のFR-813と`plan.md` 3.1、6.1を直す
